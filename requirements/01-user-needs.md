# 用户需求

本工程使用 ReqType 管理自己的需求。以下需求保持草稿状态，供后续审阅与演进。

### 本地独立使用

用户应能在 macOS 和 Windows 的本地目录中管理需求，无需登录账号或依赖团队服务器。

<!-- /req -->

### Markdown 原生与连续内容块

用户应能直接编辑 Markdown，并把任意连续内容块映射为条目，条目可包含多段文字、表格和图片。

<!-- /req -->

### 需求属性与追溯

用户应能用稳定身份、属性和类型化关联组织需求，查看关联的来源和目标。

用户应能通过 Git 审阅和记录需求变化，并导入导出自己的源数据。

### 软件自身可扩展

用户应能通过软件自己的本地插件机制添加命令、校验规则和数据交换能力。

### 项目级管理

用户应能将一个本地目录作为项目，并可对应一个 Git 仓库，为项目管理需求编号前缀、本地状态工作流、通用默认值和导出偏好。项目设置可随需求文件迁移。

<!-- /req -->

### 离线技术文档

程序员、软件架构师和产品经理应能在需求文档中编写代码、架构图、公式、任务和说明，使用扩展语法与本地插件。核心渲染资源应在本地提供，不强依赖互联网；PlantUML 可选本地 JAR 或 Server。

<!-- /req -->

### 数据格式可持续演进

用户应能继续使用已有项目，清楚检查应用是否兼容其数据格式；需要升级时应能预览、备份并恢复，不因格式演进丢失正文、身份、关联或附件。

<!-- /req -->
