# 使用说明

## 管理本工程的需求

启动开发版，或在已打包的应用中选择“打开项目”，选择本项目根目录。`.reqtype/project.yaml` 将文档目录指定为 `requirements/`，包含用户需求、系统需求与验证用例三个模块。

这些文件就是需求源数据，可以用普通文本编辑器阅读、修改或通过 Git 管理。索引在内存中生成，重新打开工作区时重建。

## 编写与条目化

1. 在左侧打开模块，直接编辑 Markdown；顶部可切换实时预览和源码。
2. 选择一个段落、整张表格或连续内容，点击“选区转条目”。软件会扩展到完整块边界并添加稳定 ID。
3. “新建条目”在文档尾部追加条目，采用项目的初始状态、默认类型与优先级。编号采用项目前缀和位数，序号在现有同前缀最大值后递增。
4. 点击条目正文或绿色属性标记，在右侧调整编号、类型、状态、优先级和标签；自定义属性可展开 JSON 编辑。
5. 使用“复制条目”生成新 ID，使用上下箭头在模块内移动条目。跨模块移动目前通过源码剪切粘贴完成，保持整个起止块完整。
6. 点击保存，或使用 `⌘/Ctrl+S` 保存当前文档，`⌘/Ctrl+Shift+S` 保存全部文档。

首版仅在文档顶层建立条目，可包围完整列表、引用、表格和多段内容；不在单个列表项、引用容器内部或表格单元格中建立独立条目。条目不嵌套。

实时预览支持标题、强调、删除线、行内代码、链接、表格、Markdown 图片，以及代码高亮、图形、公式和任务等扩展，见 [技术文档与离线渲染](markdown-features.md)。点击表格或图片可进入相应源码；更复杂的格式可切换源码编辑。

正文与属性修改共享撤销记录，切换视图保留最近文档的会话。保存是显式操作；退出时有未保存内容会提示。程序退出不会将未保存草稿作为自动恢复副本持久化。

## 检索与追溯

进入“条目”视图，搜索编号、正文、模块路径或标签，并按状态筛选。搜索也会匹配正文中提到的其他需求编号，因此结果可能包含引用者。

表格内可按项目工作流修改状态；点击编号回到正文。在右侧选择关系类型及目标后添加关联。关系以目标 UUID 保存，显示可读编号，反向关联自动计算。删除目标后保留断链提示。

重复 ID、重复编号、边界错误、未定义属性值及缺失目标会显示在检查结果中。语法有歧义时可继续编辑和保存源码；结构化编辑及完整导出会要求先修复相应错误。

## 外部修改与 Git

应用获得焦点时定期检查磁盘，也可从“更多操作”手动刷新。干净文档自动载入外部修改；有未保存编辑时保留本地内容并展示冲突。

- “保留本地编辑”表示下一次保存以用户选择的本地文本写入，仍会检查磁盘是否再次变化。外部文件已删除时，保存会重新创建文件。
- “使用磁盘版本”丢弃此文档未保存编辑并载入磁盘状态。

进入“版本”视图可初始化本地 Git、查看修改、文件差异和最近 30 次提交。先保存文档，再选择要提交的文件并填写说明。只有选中文件进入本次提交，未选中文件的既有暂存状态保留。提交身份留空时使用已有 Git 配置；填写的身份仅用于本次提交。

首版不内置拉取、推送和分支切换；可使用外部 Git 工具。切换后刷新工作区，遇到合并标记先用源码或外部工具处理。

## 数据交换

“更多操作”提供 Markdown／JSON 导入，以及保存并导出。

- 工作区 JSON 包包含文档、项目配置、附件及逐文件 SHA-256。导入先检查版本、路径、内容和条目，再展示新增、更新和相同文件。
- 勾选需要写入的文件并应用。同路径文件作为更新，重复身份或歧义不会静默合并。若同一模块被移动到不同路径，需要先处理路径或身份冲突。
- 文档引用的本地附件必须存在并纳入配置的附件范围，完整导出会检查这些引用。单文件 Markdown 不携带附件，包含图片的迁移优先使用 JSON 包。
- 导入前先保存未完成修改。多文件写入使用本地恢复日志，中断后重新打开工作区会尝试恢复；若文件随后又被外部修改，会保留该版本并报告恢复位置。

恢复日志位于 `.reqtype/local/transactions/`，其中包含导入前文件副本。它不纳入 Git，也不随 JSON 包导出。确认导入结果后，可自行清理历史日志。

当前单份文档上限 8 MB，原生交换包解码后上限 128 MB。大型附件或大量条目的性能目标仍待真实规模验证。

## 配置与插件

左侧“设置”进入项目设置页。一个项目对应一个本地根目录，可独立初始化 Git，也可以使用现有仓库。项目配置在 `.reqtype/project.yaml`，随 Git 和原生交换包迁移；应用的最近打开位置和插件启用状态属于本机数据。

- **项目与编号**：名称、说明、稳定项目 ID、需求前缀、编号位数、默认类型及优先级。旧项目首次保存设置时补充项目 ID。前缀变更仅影响新建、复制和内置文本导入，不修改既有编号或条目 ID。复制条目使用新初始状态。
- **本地工作流**：配置状态列表、初始状态和允许的下一步；空列表表示终态。默认 `draft → reviewed → approved`，并提供返工与废弃路径。属性面板和表格仅提供允许的状态转换；直接修改 Markdown 或导入文件可设置已定义状态，不执行审批。删除仍在使用的状态会被阻止。
- **通用设置**：启动默认显示文档或表格，启用编辑器拼写检查，配置扫描的文档／附件范围。扫描范围调整后重新发现文件，不搬迁或删除磁盘文件。未保存文档会先保存，再应用设置。
- **导出设置**：默认 JSON 或当前 Markdown、文件名模板、JSON 缩进。模板支持 `{project}`、`{date}`（UTC 日期）和 `{module}`，扩展名自动添加。“更多操作 → 按项目设置导出”使用默认格式；仍可单独选择 JSON 或 Markdown。完整 JSON 始终携带已管理附件。
- **类型与属性**：编辑条目类型、优先级、关联类型列表，自定义属性定义使用 JSON，支持 `string`、`number`、`boolean`、`enum`。删除仍在使用的定义会被阻止。

设置修改需显式保存。切换项目或退出时有未保存设置会提示；在应用内切换视图保留草稿。“重新载入设置”会丢弃设置草稿并读取磁盘。若外部修改了配置，保存会拒绝覆盖，重新载入后再修改。未知扩展字段和配置注释保留，但设置保存可能规范化 YAML 排版；Markdown 正文的局部修改规则保持独立。

“插件”视图可运行内置工具箱，并从包含 `plugin.json` 的本地文件夹安装插件。新安装插件默认停用，需要显式启用。插件开发接口与示例见 [plugins.md](plugins.md)。
