核心新增用例覆盖真实 begin/end 区间、冻结旧格式逐步迁移、版本混用拒绝、正文引用的上下文与转义、交换往返及文件改名、隐藏边界事务保护和未闭合围栏。冻结夹具保留 BOM／CRLF、未知字段、UUID、编号和正文；旧模块普通保存不自动升级。

AI 使用真实本机 HTTP 模拟服务，验证跨字节 UTF-8／CRLF 的 SSE、完整 JSON、usage、错误、截断、取消与超时。凭据存储通过注入加密 Vault 验证密文持久化、未来版本拒写和并发冲突；没有使用真实 API Key 或远程供应商。不能把模拟协议通过写成所有兼容服务或系统钥匙串环境都已验收。

桌面用例使用真实 Electron、独立临时项目与 userData，设置 `REQTYPE_E2E_BACKGROUND=1`，并断言窗口不可见、未聚焦。验收入口为 [桌面流程](../tests/e2e/desktop.spec.ts)，详细范围见[回归矩阵](regression-cases.md)。

会话回归实际复现并修复了两个缺陷：恢复编辑器时旧事务过滤器访问被替换的 StateField，以及重新解析未闭合围栏导致已知边界保护丢失。现在只有应用控制的整体扩展重配置跳过旧过滤器，用户输入仍受保护；缓存同时恢复对应的边界快照和撤销历史。文档与表格往返后继续属性编辑、撤销和正文输入均纳入回归。

## 发行包与平台边界

首轮本机 macOS arm64 包构建成功，包内 Apache-2.0 LICENSE、NOTICE 与第三方许可核对通过。但发行包桌面回归在 Playwright 连接启动进程时超时，未形成通过记录。采样曾显示进程停留在系统装载器；资源签名校验异常后，仅对本地测试包执行临时 ad-hoc 签名，严格签名检查通过，启动连接仍超时。尚不能据此确定完整根因，不能将构建或签名检查写成发行包运行通过。

开发版整轮复跑也曾在 Electron 关闭清理时超时；trace 显示该项编辑、保存与撤销断言已经完成。测试清理已增加一次 IPC 往返，确认清理状态通知已交给主进程处理；不放宽文件、身份或界面断言。保留这些失败记录，不把中止的轮次统计为整轮通过。

最终源码的一轮运行在前 12 项通过后出现 PlantUML 本地 Java 子进程失败。保持后端 20 秒截止时间、桌面 25 秒等待和 SVG 文字断言，单独复跑该项及后续 4 项均通过；因此上表按分批结果记录，不宣称该失败轮次整轮全绿。

本轮未执行真实 Windows 或 macOS x64 回归；没有开发者签名、公证或 Mac App Store 验证。已有发布流程的三平台 CI 仍需在后续 PR 中实际执行。本地临时测试包不作为发行资产。
