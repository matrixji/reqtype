## 本轮行为

当前业务格式仍为 v1；应用版本、各数据域版本、插件 API 与文件哈希分别管理。已知旧布局可兼容读取，通过设置页或命令行显式升级。普通 Markdown 不因扫描而获得身份。未来项目／模块／交换包／本机状态／事务日志／迁移备份均有拒写或拒执行保护，直接 IPC 和导入也不能覆盖未来模块。

冻结夹具证明旧模块的 BOM、CRLF、注释、未知字段、正文、UUID、编号与关联保留；文件用例核对二进制附件和交换往返哈希。迁移预览不写入，首写前完整备份，过期／变更计划拒绝，中途故障回滚；恢复保护后续人工编辑并支持重复执行。旧 pending 日志恢复前保留原文，损坏既有原文备份时停止回滚。合成 1→2→3 验证的是迁移引擎，尚无真实业务 v2。

开发版和 macOS 发行包都通过设置页实际完成检查、原文预览、升级、恢复，确认未来模块源码只读；未知插件启用状态不会自动执行插件或覆盖原文件。发行包也重新验证离线代码、Mermaid 标签、公式字体、本地 JAR、任务、脚注与插件代码块。Server 模式使用本地 HTTP 服务验证协议，不代表已测试所有第三方部署。

自动化使用临时项目与独立 userData；对话框定向到临时路径，之后的 IPC、文件事务、插件进程和 Git 操作为真实执行。未对当前正在使用的工程运行批量迁移，也未关闭此前打开的应用。

## 边界

- Windows 实机和真实系统输入法仍待验收；交叉打包不能替代运行证据。
- 中断恢复使用真实 pending 日志和启动恢复验证；本轮未做进程强杀、断电或硬件磁盘故障实验。
- 大规模附件／需求性能未在本轮扩展验证。迁移备份保留完整前后镜像，不自动清理，磁盘不足应先处理。
- 旧版 0.1.0 二进制不具备完整的新格式保护；回退前按[契约](data-formats.md)恢复相应旧文件，避免多个版本同时写同一项目。
- 发行包尚未签名／公证。构建仍提示部分前端块超过 500 kB；这不影响本轮通过的流程，但不能据此推断大型文档性能。
