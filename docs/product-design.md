# 产品与技术设计

状态：产品与技术方案。v0.1 已实现本地闭环，具体运行证据、限制及未完成的平台验收见 [validation.md](validation.md)。下文未注明实现状态的增强方案仍需后续验证。

## 产品定位与约束

ReqType 是以 Markdown 文件为基础的本地需求工作台，首版面向 macOS 和 Windows。一个工作区可包含多个模块文档，需求条目可跨模块建立类型化关联。

已确认：任意一段或连续内容块均可映射为条目，内容可包含多段文字、表格和图片。文档章节用于组织阅读，条目通过稳定标识获得业务身份，两者分别建模。

当前不开展团队账号、权限、服务器或实时协同。DOORS 只作为模块、属性和追溯等理念的参考，不开发其格式兼容适配。插件采用软件自己的机制。

## 首版功能范围

| 能力 | 首版目标 |
| --- | --- |
| 项目 | 本地目录可对应 Git 仓库，稳定项目 ID，设置前缀、默认值、工作流与导出偏好 |
| 工作区 | 扫描项目文档、配置和附件，识别外部修改 |
| 编辑 | 单栏实时预览、源码切换、大纲、撤销重做及中文输入 |
| 条目 | 将连续内容块转换为条目，修改属性，移动或复制条目 |
| 视图 | 文档视图、条目表格、当前条目的出向／入向关联面板 |
| 查询 | 按正文、编号、类型、状态及标签检索和筛选 |
| 关联 | 创建类型化关联、定位目标、检查重复 ID 和断链 |
| 数据交换 | 导入导出 Markdown 与原生 JSON 交换包，预览冲突 |
| Git | 本地状态、差异、显式提交和只读历史查看 |
| 插件 | 本地插件的加载、启停，命令、校验和交换扩展 |

内置插件已经提供 CSV 导出与按行文本导入。CSV 导入、HTML／PDF 报告、追溯矩阵、命名基线和需求层面的历史差异属于后续增强。历史文件恢复交互仍待设计。

## 数据与文件组织

建议工作区结构如下，目录名及配置字段尚未冻结：

```text
workspace/
├── .reqtype/
│   ├── project.yaml        # 格式版本、类型、属性和关联定义；纳入 Git
│   ├── cache/              # 可重建查询索引；忽略
│   └── local/              # 本机界面状态；忽略
├── modules/
│   ├── user-needs.md
│   └── system.md
├── assets/                 # 文档引用的附件；纳入 Git
├── .gitignore
└── .gitattributes
```

源数据由 Markdown 正文、内嵌元数据、项目配置及附件共同组成。索引保存派生结果，不承担源数据职责；删除缓存后应能恢复完整的当前条目和关联。

普通 Markdown 文档可以先作为文档打开。首次创建条目时，为模块添加格式版本和稳定模块标识，保留已有 front matter 字段。模块身份独立于文件名和路径。

新建文本使用 UTF-8、LF。既有文件的 BOM、换行、空白、未知字段和未修改文本应按源内容保留。若 Git 配置执行换行规范化，需区分编辑器保存行为与 Git 提交／检出行为。

## 编辑和条目操作

文档、表格与属性面板共享一份编辑会话。修改属性也产生文本编辑事务，参与同一撤销历史；切换视图不得重新序列化整份文档。

选择连续内容后执行“转换为需求”，选区扩展到完整 Markdown 块边界；表格或列表不能因转换被切成不完整结构。首版标记位于文档顶层，可包围整张表格或整个列表，暂不在单个表格单元格、列表项或引用容器内部建立独立条目。

移动条目保留身份；复制为新条目生成新身份。普通复制粘贴产生重复 ID 时应展示诊断，不能在后台自动改写关联。外部编辑器修改或 Git 检出触发重新解析；有未保存内容时展示冲突处理入口，不能直接覆盖任一版本。

## 技术边界

| 部分 | 方向与职责 |
| --- | --- |
| Electron 主进程 | 窗口、本地文件、系统对话框与 Git 适配 |
| React 界面 | 工作区导航、表格、关联、Git 与插件管理界面 |
| CodeMirror 6 | 源文本、实时预览装饰、选区、输入与撤销事务 |
| 领域核心 | 源区间、条目、属性、关联、诊断和变更操作；独立于 UI |
| 工作区适配 | 文件发现、外部变更检测、保存、附件和索引重建 |
| 插件宿主 | 扩展注册、生命周期、错误归因及 API 版本兼容 |

编辑器的语法树用于交互展示，领域解析器负责条目语义；两者共享语法规则与样例，避免对同一份源文本作出不同解释。查询索引的内存／SQLite 方案在规模验证后确定。

Electron 界面通过受限的预加载 API 调用本地操作，保留上下文隔离；Markdown 渲染不执行正文脚本。插件宿主的进程分离用于生命周期和故障管理，不能单独视为安全沙箱。

未来扩展主要通过工作区存储、查询和交换接口接入。当前不预建云端服务、CRDT 或分布式事件系统。

## Git 集成

- 打开已有仓库可查看状态、工作区／暂存区差异和历史；新工作区可由用户主动初始化仓库。
- 保存文件与 Git 提交是两个明确操作，不自动提交。
- 提交前展示文件范围和差异，只暂存用户选择的内容；保留外部工具已有的暂存状态。
- 修改、删除、重命名的文档及相关附件需要一致展示，不能用无差别暂存代替选择。
- 检测分支变化、外部提交和未解决的合并标记。存在语法冲突时保留源文档并提供诊断，暂停受影响条目的结构化编辑和交换。
- 首版不内置远程拉取、推送、凭据或完整分支管理；允许用户通过外部 Git 工具操作。
- Git 不可用时仍能编辑、保存和交换数据；可执行程序采用系统安装还是随应用分发，实施时确定。

Git 文件历史是首版的版本依据。后续需求差异可按稳定 ID 比较正文、属性和关联。命名基线还需固定项目配置、附件与关系快照，不能仅用一个可移动的标签代替完整定义。

## 数据交换

v0.1 原生 JSON 包包含 `format: reqtype`、`version: 1`、导出时间和文件列表。各文件包含相对路径、`utf8` 或 `base64` 编码内容与 SHA-256，保留模块原文、配置及附件。条目列表从源文件解析，不作为另一份权威数据。

导入分为解析、校验、预览、应用四步：根据稳定 ID 识别新建和更新，显式展示冲突及缺失附件。未知字段保留，未知版本拒绝写入并说明支持范围。导入前准备恢复副本；多文件写入需验证失败恢复，不能把单文件原子写入等同于整个工作区事务。

CSV 后续作为表格交换格式，需要明确列映射、属性类型、多值字段和关联表示。不能承诺它天然保留复杂正文、附件及所有未知扩展。

## 插件最小机制

- 首版支持用户显式安装、启用和禁用的本地可信插件；打开工作区不会自动运行其中的插件代码。
- 插件声明标识、版本、兼容 API 范围和扩展点，并提供激活／停用生命周期。
- 首批提供命令、只读校验规则、导入导出适配器；内置能力也尽量使用相同注册机制。
- 修改文档统一提交给领域变更接口，执行版本检查并加入撤销记录。交换插件先生成导入计划，由核心处理冲突和落盘。
- API 不直接暴露编辑器 DOM 或内部索引结构，便于后续调整界面和存储。
- 任意扩展语法、插件市场、复杂 UI 注入及热重载暂不作为首版目标。
