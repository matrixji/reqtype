# 实施顺序与验收标准

状态：开发路线与原始验收目标。v0.1 已进入实际构建与验证，当前结果以 [validation.md](validation.md) 为准。此文件保留后续尚未完成的目标，不代表所有平台和输入法均已验收。

## 阶段一：验证高风险设计

先建立小型 Electron、React、TypeScript、CodeMirror 6 验证工程。依赖版本在开始实施时核对并锁定，比较解析器与 YAML 源文本保留方案。

需要验证：

- 中文输入法、光标移动、选区、撤销重做，以及源码／实时预览切换。
- 标题、强调、列表、链接、表格、图片与需求属性标记的显示和编辑。
- 需求块边界与 GFM 上下文，特别是代码围栏、容器、不完整语法和 Git 冲突。
- 无修改往返、单字段修改、未知字段及注释保留、UTF-8／BOM／CRLF。
- 本机 Typora 对示例的阅读与编辑表现；只观察公开界面，不修改其安装包。
- macOS 与真实 Windows 环境中的文件路径、中文文件名和输入行为。

通过标准：未修改文件可字节保持，字段修改范围可解释，复杂内容不丢失，输入和切换无已知阻断问题。在两种系统上分别记录结果；只在 macOS 检查不能作为 Windows 验收。核心困难未解决前，不扩大到完整界面。

## 阶段二：本地工作区与编辑闭环

实现工作区创建／打开、配置加载、文件扫描、模块身份、需求转换、属性编辑及保存。建立外部文件变化检测和完整重建索引能力。

通过标准：可以创建包含正文、表格和图片的条目；重启后信息保留；外部修改会被发现；有未保存编辑时不会被后台覆盖。保存失败应保持可恢复状态。

## 阶段三：查询与追溯

实现条目表格、筛选检索、类型化关联、目标跳转和反向关联面板。建立重复 ID、重复编号、非法属性和断链诊断。

通过标准：文档与表格修改共享数据和撤销历史；移动文档后关联仍有效；删除缓存再打开可恢复全部源数据。记录文档加载、索引和编辑响应，在真实规模明确后确定性能目标。

## 阶段四：交换、Git 与插件闭环

- 定义并验证原生 JSON 交换 Schema，实现导入校验、冲突预览、恢复副本和失败恢复。
- 实现 Git 状态、差异、选择文件提交及只读历史，验证已有暂存内容不被意外纳入或覆盖。
- 实现最小插件宿主，用示例命令、校验器和交换适配器验证加载、启停与异常处理。

通过标准：导出后导入保留正文、身份、属性、关联、附件及未知字段；冲突处理不会静默覆盖本地文件。Git 提交范围与用户选择一致，保存不触发自动提交。插件可停用，错误可定位，文档修改通过统一事务处理。

## 阶段五：首版发布验证

补齐 macOS、Windows 构建与安装流程，验证首次使用、Git 缺失、目录不可写、附件缺失、异常退出和外部检出等真实场景。确定应用标识、签名、安装包及用户数据路径。

通过标准：两种系统安装后均可完成“打开工作区 → 编辑条目 → 建立关联 → 导出导入 → 查看 Git 差异并提交”的完整流程。未完成签名、兼容性或故障恢复验证的部分应如实列明。

## 后续增强与实施时决策

后续增强：CSV 字段映射、HTML／PDF 报告、追溯矩阵、需求历史差异、命名基线和团队协作。

实施时仍需确定：

- 实际需求规模及性能目标。
- 领域解析与编辑器语法的一致性方案，源区间和 YAML 局部修改的具体实现。
- 索引是否需要 SQLite，以及插件宿主进程与 API 协议细节。
- Git 采用系统安装还是随应用分发，以及历史文件恢复交互。
- 导入多文件变更的恢复策略、交换格式版本迁移和插件兼容规则。

这些属于尚未验证的工程选择，不应以文档中出现为由宣称已实现。
