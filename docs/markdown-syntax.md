# Markdown 扩展语法草案

状态：v0.1 已实现格式，文档版本为 1。目标是正文可读、边界明确、身份稳定、局部修改和 Git 差异清楚。完整文档示例见 [local-save.md](../examples/local-save.md)，已纳入解析与桌面检查；尚未承诺外部编辑器编辑往返的兼容性。

## 文档与模块

正文以 GFM 为基础。包含条目的文档在 YAML front matter 中记录格式版本和模块 ID：

```yaml
---
reqtype: 1
module: "ec80d073-f8bd-46fb-8275-4c5636826a63"
title: "本地需求管理"
---
```

`reqtype` 用于识别文档格式，`module` 是稳定模块 UUID，`title` 用于显示。已有 front matter 中其他字段保留。文件路径和标题变动不改变模块身份。

## 需求块

```markdown
<!-- req
id: "5e43d568-9e2c-4a9e-a12c-26934b450624"
key: "SYS-001"
type: requirement
status: draft
priority: high
tags: [local, storage]
attributes:
  owner: "产品组"
links:
  - type: satisfies
    target: "a58cb6b8-4702-4195-a10e-9cfa2397a9c1"
-->

软件应在离线状态下保存需求文档。

后续段落、表格、列表和图片都可以属于同一个条目。

<!-- /req -->
```

起始注释内保存 YAML 元数据，结束注释标记条目边界；其间原始 Markdown 为条目正文。标题可位于条目内或外，不决定条目身份及边界。

HTML 注释承载元数据，正文遵循 GFM。原文保留已在应用的解析、修改和文件交换检查中验证；Typora 自身的编辑往返仍需实测。[GFM 规范](https://github.github.com/gfm/#html-blocks)

## 元数据字段

| 字段 | v0.1 规则 |
| --- | --- |
| `id` | 必填，应用创建时生成 UUID；在工作区内唯一、不可随编号或位置变化 |
| `key` | 历史数据可省略；新建条目按项目前缀自动生成，项目内唯一，已有编号不可手改，关联仍使用 UUID |
| `title` | 可选的独立标题；未填写或留空时从正文提取，支持部分文字检索 |
| `type` | 条目类型；缺省为 requirement，可由项目定义扩展 |
| `status` | 状态；缺省为 draft，允许值由项目定义 |
| `priority` | 优先级，可选；允许值由项目定义 |
| `tags` | 字符串列表，可选 |
| `attributes` | 自定义属性映射；项目 v2 定义按类型可用属性，支持文本、数值、数组等；未绑定的旧值保留并提示 |
| `links` | 出向关联列表，每项包含 `type` 和目标 `target` UUID |

内部 ID 与显示编号分开。应用使用 UUID 解析关联，显示时使用可读编号或标题。未知字段按原文保留；缺省值用于解释数据，不因普通保存而自动补写全部字段。

元数据采用可映射到 JSON 的 YAML 子集，不执行自定义标签或别名。重复键、无效类型和原始注释终止符 `-->` 出现在字段内容中时应报告错误，不能静默截断或重写。

## 边界和选区规则

- 标记必须是文档顶层的独立 HTML 注释块；新写入的标记顶格书写，与正文之间保留空行。
- 起始标记首行精确为 `<!-- req`，元数据后以独立一行 `-->` 结束；结束标记精确为 `<!-- /req -->`。
- 首版需求块不嵌套、不交叉。块内部可包含正常 Markdown 容器，如整张表格、列表或引用。
- 位于代码围栏、缩进代码、行内代码或其他容器内部的相似文本不作为标记。
- 解析应结合 Markdown 块上下文和源区间，不能仅靠全文正则配对标记。
- 选区转换必须覆盖完整内容块，不能破坏表格、列表、代码围栏或已有条目。
- 编辑过程中允许暂时不完整的语法；显示诊断并保留文本，不自动补齐或吞并后续正文。

应用对有歧义的范围暂停结构化修改，仍提供源码编辑。转换单个列表项、表格单元格等更细粒度范围属于后续设计问题。

## 关联语义

| 出向类型 | 方向 | 反向显示 |
| --- | --- | --- |
| `satisfies` | 系统需求 → 用户需求 | 被满足于 |
| `verifies` | 验证用例 → 被验证需求 | 被验证于 |
| `depends_on` | 依赖方 → 被依赖方 | 被依赖于 |

类型名称和显示标签可由项目配置扩展。关系存于源条目的 `links`，入向关系由索引计算。相同源、类型和目标的重复关系应诊断。

目标暂时不存在时保留关系并显示断链。删除或移走目标不会自动删除其他条目的关联。跨模块引用使用同一工作区中的稳定 ID，首版不解析跨工作区远程关系。

## 原文保留和修改

解析输出包含模块、条目、字段、正文及诊断的源区间。偏移以解码后文本的 UTF-16 索引表示，范围采用起点包含、终点不包含；字节偏移和行列映射由文件适配层处理，实施时验证 emoji、组合字符和 CRLF。

无修改保存保留文件字节；标准属性修改按 YAML 节点源区间更新。复杂属性映射或关联数组作为一个字段修改时，使用有效的 YAML 流式表示更新该字段，其外文本、注释和未知扩展保留。源码编辑按 CodeMirror 文本变更映射回原文，保留未编辑区域的换行。

修改前检查编辑会话版本及磁盘内容版本，避免使用过期区间覆盖外部修改。正文语法错误或 Git 冲突未解决时，不应依赖失效区间执行属性修改。

## 验证要求

1. 示例可解析出三个条目、两个有效关联，表格完整属于 SYS-001。
2. 普通说明、代码示例中的伪标记、不同层级标题不会被错误条目化。
3. 缺失结束标记、嵌套标记、重复 ID、重复键及未知字段均有明确处理。
4. 移动和重命名保留 ID；复制为新条目生成新 ID，并能诊断外部复制产生的冲突。
5. 无编辑往返保持字节；修改一个属性只影响必要文本；源码、实时预览和表格视图保持一致。
