# ReqType AI

先读 [AI 契约](../../../docs/ai.md)、实际 `src/main/ai-*.ts`、`src/core/ai.ts` 与受影响的 `tests/ai.test.ts`。输入是目标服务的真实协议、配置或待修复的交互；没有真实密钥时使用本机模拟服务，不推断某个兼容供应商支持全部 OpenAI 参数。

- Provider 在主进程发请求，面板只使用限定 IPC。配置是应用 userData 的独立 `reqtype.ai` 信封，不混入项目、插件快照或原生交换。保存后的明文凭据不回传；系统安全存储不可用时不能退回明文保存。修改服务地址清除原凭据，保存检查内容版本，未知设置保留原文。
- 取消控制器先登记，再读取／解密设置，覆盖关闭面板和切换项目时的竞争；事件用请求 ID 隔离。面板在设置保存后还需检查自身是否已关闭／取消，避免取消后才启动请求。
- SSE 使用增量 TextDecoder，处理 UTF-8 和 CRLF 跨 chunk、空 choices 的 usage、完成标记和输出上限。断流、截断与错误不能产生可应用结果；网络不自动重试或跟随重定向。错误不得带入密钥或完整上游响应。
- 输入只取显式选择的文字／条目正文和指令。模型输出先预览；应用使用原源快照，拒绝过期结果及标签、模块或条目身份变化。新条目的 UUID、编号、类型和初始状态由应用确定；质量检查不提供直接替换。编辑行为同时使用项目的源文本编辑 Skill。

先运行相关 AI 核心用例；涉及 IPC／面板时运行 AI-UI 后台桌面流程，覆盖选区、预览无写入、应用／撤销、草稿与取消。需要新协议时增加独立 Provider 和真实 HTTP 契约用例，不靠扩大 catch 或允许不完整输出通过测试。验收区分本机模拟协议、真实供应商与原生发行包的实际证据。
